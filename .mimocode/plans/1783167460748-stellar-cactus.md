# План: Подготовка LoveConstructor.ru к продакшену

## Контекст
Проект — конструктор приглашений на свидание. Уже есть: Express-сервер, SQLite, JWT-авторизация (email + VK OAuth), дашборд, rate limiting. Нужно: доработать личный кабинет (CRUD ответов), усилить безопасность, подготовить к деплою на продакшен.

## Задача 2: Усиление безопасности

### 2.1 CSRF-защита
**Файл: `server/middleware/csrf.js`** (новый)
- Генерация CSRF-токена при первом запросе (cookie `csrf_token`)
- Валидация токена из заголовка `X-CSRF-Token` для unsafe методов (POST/PUT/DELETE)
- Токен передаётся в cookie httpOnly: false (чтобы JS мог прочитать), + в meta-тег для форм

**Файл: `server.js`**
- Подключить CSRF middleware для API маршрутов
- Исключить `GET /api/invitations/:id/public` и `POST /api/respond/:id` (публичные)

### 2.2 XSS-защита
**Файл: `public/dashboard.html`**
- Все динамические данные экранировать через `esc()` (уже есть, проверить использование)
- В `view.html` — убедиться что HTML из API не подвержен XSS (html загружается в iframe через Blob, что изолирует)

### 2.3 Input валидация
**Файл: `server/routes/invitations.js`**
- Валидация `title` — макс. 200 символов,strip HTML-тегов
- Валидация `html` — проверка что это валидная строка

**Файл: `server/routes/responses.js`**
- Валидация `responseId` — alphanumeric, макс. 32 символа
- Валидация `selectedDate` — формат YYYY-MM-DD
- Валидация `feedbackText` — макс. 1000 символов

### 2.4 УсилениеHelmet
**Файл: `server.js`**
- Добавить `reportUri` для CSP
- Настроить `hsts` для продакшена
- Добавить `referrerPolicy`

### 2.5 Глобальный rate limiter
**Файл: `server/middleware/rateLimit.js`**
- Добавить `globalLimiter` — 100 запросов в минуту на IP (защита от DDoS на уровне приложения)
- Подключить в `server.js` как первый middleware

## Задача 4: Монетизация — ненавязчивая реклама

### Концепция
Реклама размещается только на «пассивных» страницах — там, где пользователь уже закончил основное действие. Никаких popup, никаких рекламных блоков в конструкторе или на экране приглашения. Формат — компактные баннеры в подвале страницы.

### 4.1 Провайдер рекламы
**Рекомендация: Яндекс.Реклама (РСЯ)** — лучше всего работает для русскоязычной аудитории, простая интеграция, выплаты на российские карты. Альтернатива — Google AdSense (требует верификации сайта).

### 4.2 Где размещать (4 места)

| Страница | Место | Формат | Почему здесь |
|----------|-------|--------|-------------|
| `dashboard.html` | Подвал, после списка приглашений | Горизонтальный баннер 728×90 (десктоп) / 320×50 (мобайл) | Пользователь просмотрел свои приглашения, готов уйти — баннер не мешает |
| `login.html` | Подвал формы входа | Компактный баннер 320×50 | Экран логина — «мёртвое» пространство, баннер не перекрывает форму |
| `track.html` | Подвал, после списка ответов | Горизонтальный баннер 728×90 / 320×50 | Пользователь проверил ответы — реклама внизу, не на пути |
| `view.html` | Подвал страницы (под приглашением) | Текстовая ссылка или компактный баннер 320×50 | Приглашение рендерится в iframe, баннер снаружи — не портит впечатление |

### 4.3 Реализация

**Файл: `public/css/ads.css`** (новый)
- Стили для рекламного контейнера: центрирование, отступы, серый фон-плейсхолдер для разработки
- Адаптивность: на мобильных баннер 320×50, на десктопе 728×90

**Файл: `public/js/ad.js`** (новый)
- Модуль `AdBanner` — инициализация рекламного блока
- Загружает скрипт рекламного провайдера (лениво, по DOMContentLoaded)
- Контейнер `<div class="ad-banner">` с id для каждой страницы
- Fallback: если реклама не загрузилась — показывает компактный статичный блок «LoveConstructor.ru»

**Изменяемые файлы (добавить рекламный контейнер):**
- `public/dashboard.html` — `<div id="ad-slot-dashboard" class="ad-banner"></div>` перед `</div class="container">`
- `public/login.html` — `<div id="ad-slot-login" class="ad-banner"></div>` после `.card`
- `public/track.html` — `<div id="ad-slot-track" class="ad-banner"></div>` перед `</body>`
- `public/view.html` — `<div id="ad-slot-view" class="ad-banner"></div>` после iframe-контейнера

### 4.4 Что НЕ рекламируем
- На главной странице конструктора (`index.html`) — пользователь творит, не отвлекаем
- На экране приглашения внутри iframe (`view.html` iframe) — это личное пространство
- Всплывающие окна, интерстициалы, модалки с рекламой — запрещены

### 4.5 Ожидаемая монетизация
- РСЯ: ~0.5–2 руб за 1000 показов (CPM), ~5–30 руб за клик (CPC)
- При 1000 уникальных посетителей в месяц: ~50–200 руб/мес (реалистично для начала)
- Рост пропорционален трафику

## Верификация

1. **Запустить сервер**: `npm start` — убедиться что стартует без ошибок
2. **Тест CRUD ответов**: создать приглашение, отправить ответ через view.html, затем в dashboard: посмотреть, изменить, удалить ответ
3. **Тест CSRF**: попытка POST без CSRF-токена должна вернуть 403
4. **Тест rate limiting**: >100 запросов/мин → 429
5. **Тест продакшена**: `NODE_ENV=production` — cookie должны быть secure, stack traces не раскрываться
6. **Тест VK OAuth**: проверить редирект на VK и callback (нужны реальные VK_APP_ID/SECRET)
7. **Тест рекламы**: открыть dashboard/login/track/view — в подвале должны отображаться рекламные контейнеры (в dev-режиме — плейсхолдер «LoveConstructor.ru»)
