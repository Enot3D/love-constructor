# Love Constructor — Backend & Auth Implementation Plan

## Overview

Transform the static client-side app into a full-stack web application with user accounts, personal dashboard, and monetization. Domain: `loveconstructor.ru` (purchased last).

---

## Tech Stack

| Layer | Technology | Why |
|-------|-----------|-----|
| Server | **Express.js** (Node.js) | Simple, well-documented, flexible |
| Database | **SQLite** via **better-sqlite3** | Zero-config, file-based, good for this scale |
| Auth | **JWT** in httpOnly cookies + **bcrypt** | Stateless, secure, works with API |
| OAuth | **VK OAuth 2.0** (Passport.js) | Popular in Russia, user requested |
| Email auth | Passport-local + bcrypt | Standard email/password |
| Frontend | Existing HTML/JS + new dashboard pages | Minimal rewrite |
| Hosting | **Railway.app** or **Render.com** | Free tier, supports Node.js + SQLite |
| DDoS | **Cloudflare** (free plan) | DNS proxy, rate limiting |
| Ads | **Google AdSense** or **Яндекс.Реклама** | Non-intrusive banner ads |

## Database Schema (SQLite)

```sql
-- Users
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  email TEXT UNIQUE,
  password_hash TEXT,           -- NULL for VK-only users
  vk_id TEXT UNIQUE,            -- VK OAuth ID
  display_name TEXT NOT NULL,
  avatar_url TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  last_login DATETIME
);

-- Invitations (replaces Firebase /invitations/{id})
CREATE TABLE invitations (
  id TEXT PRIMARY KEY,           -- 8-char random ID (same as current)
  user_id INTEGER NOT NULL,
  title TEXT,
  html TEXT NOT NULL,            -- Full generated HTML
  sender_token TEXT NOT NULL,    -- 16-char secret for tracker access
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  is_active INTEGER DEFAULT 1,  -- soft delete
  FOREIGN KEY (user_id) REFERENCES users(id)
);

-- Responses (replaces Firebase /responses/{id}/{rid})
CREATE TABLE responses (
  id TEXT PRIMARY KEY,           -- session-based random ID
  invitation_id TEXT NOT NULL,
  clicked_yes INTEGER DEFAULT 0,
  selected_date TEXT,
  feedback_text TEXT,            -- future: free-form feedback
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (invitation_id) REFERENCES invitations(id)
);
```

## API Endpoints

### Auth
| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/auth/register` | Register with email + password |
| POST | `/api/auth/login` | Login with email + password |
| POST | `/api/auth/logout` | Clear session cookie |
| GET | `/api/auth/vk` | Redirect to VK OAuth |
| GET | `/api/auth/vk/callback` | VK OAuth callback |
| GET | `/api/auth/me` | Get current user profile |

### Dashboard (auth required)
| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/invitations` | List user's invitations with stats |
| GET | `/api/invitations/:id` | Get invitation details + responses |
| DELETE | `/api/invitations/:id` | Soft-delete invitation |
| PUT | `/api/invitations/:id` | Update invitation (re-publish) |
| GET | `/api/invitations/:id/responses` | Get responses for invitation |

### Public
| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/publish` | Publish invitation (auth required) |
| GET | `/view.html` | Public invitation viewer (unchanged) |
| POST | `/api/respond/:id` | Submit response from recipient |

## Key Design Decisions

1. **SQLite over PostgreSQL** — Zero config, single file, good enough for this scale. Can migrate to PostgreSQL later if needed.

2. **JWT in httpOnly cookies** — More secure than localStorage tokens. Immune to XSS. Works with server-side rendering if needed later.

3. **Keep existing Firebase as fallback** — During migration, both Firebase and new API work. Old invitations still accessible.

4. **VK OAuth** — Passport.js with `passport-vkontakte` strategy. Requires VK App ID + Secret (free to create at dev.vk.com).

5. **Static files served by Express** — No need for Nginx. Express serves `public/` directly.

6. **Single server** — API + static files on same Express app. Simpler deployment.
